# WebContainer Technology Research — Primary-Source Baseline

> Research date: 2026-11-06. Sources: webcontainers.io (Introduction, API
> Reference, Configuring Headers, Working with the File System, Running
> Processes guides), blog.stackblitz.com (Introducing WebContainers),
> github.com/stackblitz/webcontainer-core issue #560. Every claim below was
> read from the live page this date; nothing is from memory or third-party
> summaries. This document is the parity baseline for the OpenContainer
> public API and the A–F audit (`docs/AUDIT.md`).

## 1. What WebContainers is

A **browser-based runtime for executing Node.js applications and operating
system commands entirely inside a browser tab** (webcontainers.io,
Introduction). Commercial product of StackBlitz; "always free for Open
Source" projects; commercial usage requires their license (pricing page).
Battle-tested via the StackBlitz editor and the Svelte/Angular/Nuxt
interactive learning environments. Announced at Google I/O.

## 2. Architecture (from the announcement blog)

- Built with **WebAssembly + new browser capabilities APIs** — a
  "WebAssembly-based operating system" running Node.js entirely client-side.
- **Virtualized TCP network stack** mapped to the browser's **ServiceWorker
  API** — live Node.js servers, work offline.
- **Custom built-in npm client**; **fresh installs on every page load** —
  clean environments without a local `node_modules` that persists.
- Execution stays inside the browser security sandbox; Chrome DevTools can
  attach for native back-end debugging; File System Access API for local FS
  read/write; PWA-capable.
- Claimed: builds up to 20% faster than local, package installs 5×+ faster
  (vs. cold local environments with cold FS caches).

Not stated publicly: the exact syscall-interception layer, memory model, or
process limit — those are proprietary internals.

## 3. Requirements

- The embedding page MUST be served with **COOP: same-origin** and **COEP:
  require-corp** (or **credentialless**, in which case boot must receive
  `coep: 'credentialless'`) — because WebContainers **require
  SharedArrayBuffer**, which requires cross-origin isolation
  (webcontainers.io/guides/configuring-headers).
- `coep: 'none'` (no isolation headers) works only on Chromium-based
  browsers while a StackBlitz **Origin Trial** is active.
- Per-platform header configuration is documented for Cloudflare, Netlify,
  Vercel, SvelteKit, Nuxt 3, Next.js.

## 4. Public API surface (exact, from the API reference)

### 4.1 `WebContainer` class

| Member | Signature | Semantics |
|---|---|---|
| `boot` | `static boot(options: BootOptions = {}): Promise<WebContainer>` | Boots a container. **Only one instance can be booted concurrently**; booting is expensive. |
| `mount` | `mount(tree: FileSystemTree \| Uint8Array \| ArrayBuffer, options?: { mountPoint?: string }): Promise<void>` | Mounts a file tree, or a **binary snapshot** generated by `@webcontainer/snapshot`. |
| `spawn` | `spawn(command: string, args: string[], options?: SpawnOptions): Promise<WebContainerProcess>` (also `spawn(cmd, options?)`) | Runs a command. |
| `on` | `on(event, listener): () => void` | Subscribes; returns an **unsubscribe function**. |
| `teardown` | `teardown(): void` | Destroys the instance, releases resources. |
| `fs` | property: `FileSystemAPI` | Filesystem access. |
| `path` | property: `string` | Default `PATH` env value for spawned processes. |
| `workdir` | property: `string` | Full path of the working directory. |

`BootOptions`: `coep?: 'require-corp' | 'credentialless' | 'none'`;
`workdirName?: string` (folder name of the working dir; "mostly cosmetic";
auto-generated when absent); `forwardPreviewErrors?: boolean |
'exceptions-only'` (default `false`; forwards `console.error`,
`unhandledrejection`, uncaught `error` from preview iframes as
`preview-message` events).

`SpawnOptions`: `cwd?: string`; `env?: Record<string, string | number |
boolean>`; `output?: boolean` (disable output collection); `terminal?:
{ cols: number; rows: number }`.

### 4.2 Events

- `'server-ready'`: `(port: number, url: string)` — a server started and is
  ready to receive traffic.
- `'port'`: `(port: number, type: 'open' | 'close', url: string)` — a port
  was opened/closed by some process.
- `'error'`: `(error: { message: string })` — internal error.
- `'preview-message'`: `(message: PreviewMessage)` — forwarded errors from
  preview iframes. `PreviewMessage` = (`UncaughtExceptionMessage` |
  `UnhandledRejectionMessage` | `ConsoleErrorMessage`) & `{ previewId, port,
  pathname, search, hash }`.

### 4.3 `FileSystemTree` (mount format)

```ts
interface FileSystemTree { [name: string]: FileNode | SymlinkNode | DirectoryNode }
interface FileNode      { file: { contents: string | Uint8Array } }
interface SymlinkNode   { file: { symlink: string } }   // ← first-class symlinks
interface DirectoryNode { directory: FileSystemTree }
```

### 4.4 `WebContainerProcess`

`exit: Promise<number>` · `input: WritableStream<string>` · `output:
ReadableStream<string>` (stdout AND stderr merged) · `kill(): void` ·
`resize({ cols, rows }): void`. **No `stderr` stream** in the documented
interface; output is merged.

### 4.5 `FileSystemAPI` (from the FS guide)

- `readFile(path)` → `Uint8Array`; `readFile(path, 'utf-8')` → `string`.
- `readdir(path)` → `string[]`; `readdir(path, { withFileTypes: true })` →
  `Dirent[]` (`name`, `isFile()`, `isDirectory()`); `readdir(path, {
  encoding: 'buffer' })` → `Uint8Array[]`.
- `writeFile(path, contents: string | Uint8Array)` (contents may carry an
  encoding option, e.g. latin1).
- `mkdir(path)` / `mkdir(path, { recursive: true })`.
- `rm(path)` / `rm(path, { recursive: true, force? })`.
- Watching exists in newer API versions (`watch(path, listeners, options)`
  with `onWatchEvent`/`onWatchError`/`onWatchReady` and change records
  `{ path, type: 'created' | 'updated' | 'renamed' | 'deleted' }`).
- Paths are container paths; examples use absolute paths rooted at the
  working directory (e.g. `'/package.json'` — the workdir is the container
  root for user mounts).

## 5. Runtime identity & package managers

- **Node.js 24 is the current default**; projects can pin **Node 22** via
  `engines.node`, `.nvmrc`, or `.tool-versions` (GitHub issue #560, Jan 2022
  thread updated 2025-2026). Version is chosen per project at boot.
- npm is the primary client (docs show `spawn('npm', ['install'])`,
  `npm run start`). The runtime ships its own package-manager stack inside
  the image (jsh + npm; pnpm/yarn available via corepack in practice).
- The processes guide shows no shell API — `spawn` takes a command directly;
  interactive terminal flows are built on top by embedders (e.g. StackBlitz
  Codeflow), not exposed by this API.

## 6. The 15 investigation points (summary matrix)

| # | Question | Answer (source) |
|---|---|---|
| 1 | Distribution | npm package `@webcontainer/api`; assets loaded from their CDN at boot |
| 2 | Boot cost | "expensive", single concurrent instance, `teardown()` to re-boot |
| 3 | Isolation requirement | COOP+COEP mandatory (SharedArrayBuffer); `coep:'none'` = Chromium origin trial only |
| 4 | Node version | Default 24, pinnable to 22 via engines/.nvmrc/.tool-versions |
| 5 | Process model | One `spawn` per command; `WebContainerProcess` streams; no public child-process API |
| 6 | Events | server-ready, port, error, preview-message (+ unsubscribe fn) |
| 7 | FS API | readFile/readdir(+Dirents,buffer)/writeFile/mkdir/rm/watch |
| 8 | Mount format | FileSystemTree with **symlinks** or binary snapshot |
| 9 | Persistence | None built-in — fresh npm install every load (their blog); snapshots via separate package |
| 10 | node_modules | Re-installed per session (custom npm client, cached at the CDN/HTTP layer) |
| 11 | Networking | Virtual TCP stack → ServiceWorker; preview URLs per port; outbound HTTP(S) allowed via fetch proxying |
| 12 | Preview errors | forwardPreviewErrors + preview-message (console.error/unhandledrejection/uncaught) |
| 13 | Terminal | No public PTY API; `terminal: {cols,rows}` spawn option + `resize()` |
| 14 | Shell | jsh (proprietary); not exposed in the public API |
| 15 | Licensing | Free for OSS; commercial license required (pricing/console) |

## 7. Parity implications for OpenContainer (design inputs)

1. **A `WebContainer` facade class is required** for drop-in adoption:
   `WebContainer.boot()`, `.mount()`, `.spawn()`, `.on()`, `.teardown()`,
   `.fs`, `.path`, `.workdir` — on top of `OpenContainerRuntime`.
2. **Symlink nodes** must be accepted by `mount` (our VFS already models
   symlinks — expose them).
3. **`spawn` must return a process object** with merged `output` +
   `input`/`exit`/`kill`/`resize` — a programmatic (pipe-stdio) spawn, not
   only the terminal foreground spawn.
4. **Unsubscribe-returning `on()`** (our event map exists; add the facade
   shape).
5. **No COOP/COEP requirement** is a FEATURE we keep (our engine needs no
   SharedArrayBuffer; polyfilled only when absent).
6. **Persistence is our advantage**: OPFS-persisted source files + ephemeral
   node_modules is *beyond* the WebContainer baseline (they reinstall every
   load); keep and document.
7. `coep`/`workdirName`/`forwardPreviewErrors` boot options: accept for
   compatibility; `coep` is a no-op (documented), `workdirName` is honored,
   preview-error forwarding maps to our runtime error events.
